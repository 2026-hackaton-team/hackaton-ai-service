# 경조사 가상 시나리오 목록

> 모든 사람·관계·행사·장소·금액은 허구다. 기준일은 2026-10-30이다.
> 기대 결과는 검토할 목표이며, 각 사례의 실모델·브라우저 실행 상태는 `NOT_RUN`이다. 모델 대역이나 자동 테스트 통과를 실제 모델 품질로 해석하지 않는다.

이 문서는 SQLite 시드 `data/gyeongjosa_seed.sqlite3`의 `scenario_cases` 자료에 보존된 80개 사례를 사람이 검토하기 쉽게 정리한 **테스트 계약**이다. 각 사례의 사전 조건, 질문, 기대 결과, 금지 동작, 참조 ID와 선행 조건은 시드 자료에도 기록돼 있다. 이전 JSON 원본은 `data/json_backup/`에 보관된다.

가상 계정 선택은 운영 인증이 아니다. 실행 중 시드 데이터는 SQLite에서 읽고, 로그인 계정의 인맥·일정·장부는 별도 서버 SQLite 작업공간을 기준으로 조회한다. 현재 React의 상담 진입점은 통합 AI 화면이며, 이 80개 테스트 계약의 기대 결과를 실모델 평가나 현재 일반 상담의 통과 결과로 간주하지 않는다.

## 초기 시나리오 데이터와 확장 범위

- 기존 원본에는 결혼·장례·백일·돌·생일·환갑·칠순·팔순과 기대 근거가 기록된 질문 13개가 있다. 기존 시제품에는 가상 상황 100개가 있으나 질문이 제한된 문장 패턴을 반복한다.
- 새 고정 자료는 기존 111명의 데이터를 보존하며 사용자 6명과 행사·거래·소식을 추가한다. 각 사례는 질문뿐 아니라 사전 조건, 기대 결과, 금지 동작과 자료 식별자를 함께 기록한다.
- 통합 화면의 일정 입력은 기존 행사 데이터의 전체 8개 유형과 일치하지 않고, 장부 입력은 명시적 0원을 허용하지 않는다. 출생·입학·퇴직 같은 확장 사례와 공동 정산은 현재 구현 완료가 아니다.
- 아래 목록은 검토를 위한 초기 범위다. 법적 판단, 금액의 적정성, 전체 사용자 분포를 입증하지 않는다.

### 1. 공유 부고와 동명이인

1. `SCU001`은 직접 친구가 공유한 `SCN001` 또는 친구의 친구가 공유한 `SCN002`를 확인한다.
2. 상주 김가람과 이름이 같은 `SCP001`·`SCP002`의 소속을 비교하고 사용자가 동일인을 확인한다.
3. 확인된 `SCP001`의 과거 받은 기록 `SCT001`·`SCT005`와 낸 기록 `SCT006`·`SCT025`를 구분한다.
4. 사용자가 현재 예산과 참석 가능 시간을 제공하면 그 입력과 과거 거래를 나눠 살펴본다. 확인 전 이력 연결·자동 발송·자동 참석 기록은 하지 않는다.

### 2. 기록이 없는 새 지인

1. `SCU002`가 새 동료 `SCP004`의 예정 행사 `SCE032`를 확인한다.

3. 개인 이력이 없을 때 공개 설문을 금액 근거로 활용할지는 팀 정책 결정 항목이다.

### 3. 조문 가능 시간과 불참

3. 대화에서 고려한 계획을 실제 참석이나 송금으로 자동 저장하지 않는다. 여러 의도의 동시 처리와 일정 수정은 기능 확장 항목이다.
