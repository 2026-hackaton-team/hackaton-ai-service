# 마음결 작업 기록·확인할 문제

## 2026-10-31: 서비스명 통일 / 사이드바 정리

- 서비스 이름을 **마음결**, AI 기능 이름을 **마음결 AI**로 통일했다. React, 별도 v4 화면, 구형 웹 화면, API 제목, 실행 로그, 문서를 함께 수정했다.
- 사이드바 헤더 순서를 로고·마음결 이름 → 햄버거 버튼으로 변경했다. 모바일 닫기와 접기/펼치기 기능은 유지한다.
- 후속 명세 R04에 따라 경조사 예절은 상단 마지막, AI는 하단 메뉴로 분리했다. 낮은 화면은 사이드바를 스크롤할 수 있다.
- 예절 공통 설명을 짧게 다듬었다. 행사별 안내·출처·AI 자유 상담·v4 분석·부고 추천·가입·인맥·장부 기능은 제거하지 않았다.
- `docs/NEXT_WORK_SPEC.md`에 기존 후속 명세를 가져왔다. 원본의 최초 현황은 이전 버전 기준이며, 코드 위치는 이제 `frontend/src`, `gyeongjosa_ai`, `app`, `v4_demo_frontend`로 나뉜다.

## 기능을 유지하며 남겨 둔 사항

1. **데이터 원천 미통합 (R00/R03)**: React 인맥·일정·장부는 브라우저 저장, 자유 상담은 별도 합성 자료·대화 SQLite, v4는 별도 합성 자료·프로필 SQLite다. 일반 CRUD를 수정해도 AI 자료에 자동 반영되지 않는다.
2. **일정 → AI 대상 전달 (R03/R04)**: 일정 상세에서 AI를 열 수 있지만 기존 인맥 ID를 새 자유 상담 화면의 선택 대상으로 전달하지 않는다. 기능 삭제로 해결하지 않고 연결 작업을 남겨 둔다.
3. **계정·친구 기능 (R00~R02)**: 실제 인증, 가입 단계의 추가 프로필, 회원 추천 카드·친구 요청/수락·거절·연결 배지는 아직 미완료다. v4 프로필과 가상 관계를 실제 기능 완료로 간주하지 않는다.
4. **가독성·접근성 (R05/R06)**: 사이드바 메뉴 버튼 이외의 기존 작은 글자·작은 터치 영역과 보조공학 검증은 별도 작업이다. 이번 이름 변경으로 전체 접근성 완료를 선언하지 않는다.
5. **브랜치 상태**: 작업 시작 시 로컬 develop은 origin/develop보다 2개 커밋 뒤로 표시됐다. 자동 pull·reset·merge는 하지 않았으므로 추후 동기화 시 현재 변경을 보존해야 한다.
6. **기존 저장소 호환성**: `maeum-*` 브라우저 저장 키, `rag-demo-user`, DB 파일명·API 경로·사용자 환경변수는 유지했다. 실행기의 이전 `.onmaeum-requirements`는 기존 설치를 인식하는 호환용 읽기에만 남기고 새 표식은 `.maeum-gyeol-requirements`를 사용한다.

## 검증

- 프런트 단위 테스트 **45개 통과**, Vite 프로덕션 빌드 통과.
- 화면에서 데스크톱 헤더의 브랜드 → 햄버거 순서, 접기/펼치기, 상단 예절·하단 AI, 360px 모바일 메뉴 열기/닫기를 확인했다. 주요 기능 메뉴는 모두 유지했다.
- 표시용 이전 서비스 이름은 검색 결과에서 제거했다. 영문 이전 이름은 설치 캐시 호환 코드와 이 설명에만 남는다.
- Python 3.14.4 / Windows에서 UTF-8 모드 전체 테스트: **164 passed, 5 failed, 39 subtests passed**, 비차단 경고 1건. 전체 통과로 표시하지 않는다.
- 기본 인코딩 실행은 CP949 읽기 오류와 정리 단계 오류도 발생했다. `$env:PYTHONUTF8='1'` 설정 후 인코딩 오류는 해소됐지만 아래 5개 실패는 남았다.
- 실제 외부 LLM 호출·운영 인증·화면 전체의 보조공학 검증은 이번 범위에 포함하지 않는다.
- 실행 중인 서버는 자동 재시작하지 않았다. Python API 제목과 실행기 안내의 변경은 서버를 다시 실행하면 반영된다.

## 로컬 시연영상 목표 전환 / 친구 탭·받은 일정 미리보기

- 현재 목표는 실서비스 배포가 아닌 **로컬에서 촬영할 수 있는 시연 완성도**다. 이전 문서의 운영 인증·DB·Web Push 선행 조건은 실서비스 확장 항목으로 남긴다.
- 인맥 관리에 **내 인맥 / 친구 찾기 / 받은 요청** 탭과 인맥 추가 버튼을 배치했다. 기존 수동 인맥 검색·필터·상세·편집·장부 연결을 유지한다.
- 친구의 친구 카드·공통 친구 수·프로필, 받은 요청의 수락·거절 배치를 가상 자료로 미리 볼 수 있다. 예시는 숨길 수 있고 이름·소속으로 검색할 수 있다. 실제 요청 버튼은 비활성 상태이며 전송·수락 성공 상태를 만들어내지 않는다.
- 일정 관리에 **받은 일정** 창을 추가했다. 빈 상태, 가상 수신 일정 목록·상세를 제공하고 내 달력에 자동 추가하지 않는다. 기존 공유 부고 추천·일정 등록·달력·참석 상태는 유지한다.
- 실제 회원 관계·받은 요청 알림·일정 송수신·경조사 일괄 발송은 미구현이다. 미리보기 자료를 서버 회원/알림/개인 기록으로 저장하지 않는다.
- 개선 우선순위와 시연 흐름은 `docs/LOCAL_DEMO_REVIEW.md`에 정리한다.

### 이번 미리보기 변경 검증

- 기존 프런트 단위 테스트 45개 통과, Vite 빌드 통과.
- 브라우저에서 친구 예시 검색·프로필 열기/닫기·방향키로 받은 요청 탭 전환을 확인했다.
- 받은 일정의 빈 상태·가상 목록·상세·목록 복귀를 확인했다. 실제 수신/발송/수락 요청은 발생하지 않는다.
- 백엔드는 수정하지 않았으며 앞서 기록한 Python 테스트 실패 5개는 이번에 재실행하거나 해결하지 않았다.

- 360px 모바일에서 친구 탭과 받은 일정 목록을 확인했고, 받은 일정 제목·버튼 배치를 조정해 가로 넘침 없이 표시되는 것을 확인했다.
- 기존 인맥 추가 창이 정상적으로 열리는 것을 확인했다. 검수 중 새 인맥·일정은 저장하지 않았다.


## 공유 부고: 일정 화면에서 알림 카드로 이동

- 요청한 일정 상단의 ‘친구와 친구의 친구가 공유한 부고’ 제목·안내·빈 상태 영역을 제거했다. 조회 기능은 상단 알림함으로 옮겼다.
- 알림함에 **공유 소식** 분류와 부고 카드·상세·읽음 표시를 추가했다. 기존 일정 알림·모두 읽음·브라우저 알림 설정을 유지한다.
- 알림함에서 시연 계정을 직접 선택할 수 있고 AI 자유 상담의 계정과 동기화한다. 계정을 바꾸면 이전 공유 소식을 비우고 이전 조회를 취소한다.
- 공유 소식 읽음 ID는 계정별로 구분한다. 새 계정에 이전 계정의 읽음 상태를 적용하지 않는다.
- 기존 공유 허용 필터를 거친 `/api/notices` 자료를 사용한다. 친구 수락 요청·직접 받은 일정과는 구분하며, 서버 발송·Web Push를 새로 구현한 것은 아니다.
- 공유 부고 상세의 AI 이동을 유지한다. 실제 계정 인증과 AI/v4 데이터 일원화는 여전히 별도 작업이다.

### 이번 알림 이동 검증

- 기존 45개와 신규 5개를 합친 프런트 테스트 **50개 통과**, 프로덕션 빌드 통과. 신규 검증은 계정별 조회/읽음 구분, 중복 소식, 요청 취소/실패, 계정 동기화를 다룬다.
- 브라우저에서 일정 상단 영역이 사라지고 받은 일정·일정 등록·달력이 유지됨을 확인했다.
- 알림함에서 U001 계정을 선택해 실제 시연 API의 부고 카드 2개가 표시됨을 확인했다. 상세·목록 복귀·읽음 표시를 검수했다.
- 알림에서 U002로 바꾼 계정이 AI에 반영되고, AI에서 U001로 바꾼 계정이 알림에 반영되는 것을 확인했다. U001의 읽음 상태도 유지됐다.
- 백엔드 발송·Web Push·실제 친구 요청은 이번 변경에 포함하지 않는다.
