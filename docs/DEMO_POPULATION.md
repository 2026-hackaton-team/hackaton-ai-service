# 발표용 100명 인맥·2촌 추천 시연

## 기준과 범위

- 서버 계정·작업공간·공유 소식은 기존 SQLite에 저장하며 브라우저 저장소를 사용하지 않습니다.
- 기존 `test1234` 상담용 인맥 22명·거래 100건·일정 122건과 20개 검증 시나리오는 보존합니다.
- 신규 합성 인맥 78명(친밀도 1~5점, 다양한 관계·양방향 거래·예정 행사)을 1회 추가합니다.
- 일반 회원 100명을 무더기로 가입시키지 않습니다. 발표용 추가 로그인 계정은 수신자와 중간 회원 두 개뿐입니다.
- 이 자료의 분포는 실제 인구 통계가 아니라 추천 시연용 분포입니다.

## 적용 명령

최신 `develop`을 반영한 다음 백엔드 가상환경에서 저장소 루트 기준으로 실행합니다.

```bash
python -m gyeongjosa_ai.demo_population
```

명령은 변경 전에 기존 계정·작업공간·공유 행사 SQLite를 `data/runtime_backup_*/`에 백업합니다. 존재하지 않는 DB는 백업하지 않습니다. JSON 시드 DB, RAG·법률·물가 근거, 대화 DB는 덮어쓰지 않습니다. 기존 계정의 비밀번호를 자동 초기화하지 않으며, 합성 계정 ID가 이미 다른 비밀번호로 사용 중이면 오류를 보고하고 중단합니다.

시드는 사용자별 고정 키로 적용하여 두 번 실행해도 인물·장부가 중복되지 않습니다. 기존 인물의 수정·삭제와 공유 소식 철회를 되돌리지 않습니다. 이미 인맥을 수동으로 추가했거나 기존 22명을 삭제한 계정은 정확히 100명이 아닐 수 있습니다.

## 발표 로그인

| 역할 | 로그인 ID | 비밀번호 | 서버 사용자 ID |
|---|---|---|---|
| 상담·공유 발행 | `test1234` | `test1234` | `TEST1234` |
| 공유 추천 수신 | `test12345` | `test1234` | `ACC:test12345` |
| 2촌 연결용 중간 계정 | `testbridge` | `test1234` | `ACC:testbridge` |

세 계정은 **로컬 합성 시연 전용**입니다. 서비스 공개 운영이나 실사용자 데이터 입력에 사용하지 않습니다. 발표자는 `test1234`와 `test12345`만 로그인하면 됩니다.

## 2촌 추천 구조

```text
test1234 -- 수락된 친구 -- testbridge -- 수락된 친구 -- test12345
test1234 ---------------- 직접 친구 관계 없음 ---------------- test12345
```

`test1234`가 작성한 "[합성 2촌 시연] 테스트 사용자의 결혼 소식"을 공유 동의 확인·친구의 친구 범위·참석 허용 조건으로 서버에 저장합니다. `test12345`에게는 `friend_of_friend` 이유로 추천됩니다. 서로 직접 친구가 아니므로 직접 친구 추천으로 분류되지 않습니다.

## 시연 확인 순서

1. 위 적용 명령의 결과에서 `main_people`이 100, `recipient_people`이 15, `recommendation_reason`이 `friend_of_friend`인지 확인합니다.
2. `test1234`로 로그인해 인맥·장부·예정 일정을 확인합니다. 기존 20개 일반 상담 시나리오를 그대로 재현할 수 있어야 합니다.
3. 로그아웃 후 `test12345`로 로그인해 별도 인맥·장부를 확인합니다.
4. 공유 일정 추천에서 합성 결혼 소식을 확인합니다. 이전 계정의 개인 거래 내역은 볼 수 없어야 합니다.
5. 서버의 `/api/account/social` 응답에서 수락 연결 2건과 양 시연 계정 간 직접 연결 부재를 확인합니다.
6. `/api/shared-events/recommendations`에서 해당 소식의 `reason_code`가 `friend_of_friend`인지 확인합니다. 이미 공유를 철회했다면 재실행하더라도 자동 복구되지 않습니다.

기존 `test1234`와 `test12345`가 이미 직접 친구로 연결되어 있다면, 기존 사용자의 관계를 강제로 삭제하지 않고 적용을 중단합니다.

## 검증

```bash
python -m pytest -q tests/test_demo_population.py tests/test_demo_test_account.py tests/test_demo_server_state.py tests/test_shared_events.py tests/test_workspace_storage.py
```

배포 대상 서버의 실제 SQLite는 Git에 포함되지 않으므로 저장소 병합만으로 서버 시연 데이터가 자동 주입되지는 않습니다. 적용 명령은 **시연에 사용할 그 서버 환경**에서 실행해야 합니다.
