# 마음결 로컬 시연영상 점검

## 현재 목표와 이번 변경

목표는 서비스를 운영 배포하는 것이 아니라 **로컬에서 핵심 흐름을 이해하기 쉽게 촬영하는 것**이다. 기존 기능을 삭제하거나 실패를 가짜 성공으로 바꾸지 않는다. 준비된 기능, 가상 자료로 시연하는 기능, 향후 연결할 화면을 구분한다.

- 추가: 인맥 관리의 **친구 찾기 / 받은 요청** 탭과 가상 카드·프로필 미리보기.
- 추가: 일정 관리의 **받은 일정** 창, 가상 목록·상세 미리보기.
- 유지: 기존 인맥·일정·장부·가입·공유 부고·AI 자유 상담·v4 분석.
- 미구현: 실제 친구 요청·수락/거절·상단 요청 알림, 일정 수신/저장·일괄 발송. 미리보기의 관련 버튼은 비활성으로 표시하고 서버 요청/개인 기록 변경을 하지 않는다.
- 친구 추천은 **사람 추천**, 공유 부고는 **소식 추천**, 받은 일정은 **나에게 직접 온 초대**다. 세 종류를 같은 기능처럼 설명하지 않는다.

## 촬영 전에 개선하면 좋은 순서

| 보통 | 친구 찾기·요청·받은 일정의 실제 서버 기능은 없음 | 이번에 탭·창·가상 예시를 마련. 영상에서는 **연결 예정 화면**으로 짧게 소개. 실제 발송·수락됐다고 설명하지 않음 |
| 보통 | Python 테스트 5개 실패가 남음 | `WORK_NOTES.md`의 경로·체크섬·Windows DB 잠금을 후속 수정. 실패한 테스트 삭제/제외로 해결하지 않기 |

실서비스 인증·계정별 DB 전체 이전·예약 Web Push·음력/반복 일정은 시연 범위를 넘는 후속 작업이다. 미완성 기능은 보존하고 현재 한계를 설명한다.

## 짧은 영상 흐름 예시

1. 홈 → 일정·인맥·장부에서 서비스 목적과 기록 흐름을 소개한다.
2. 인맥 관리의 친구 찾기·받은 요청, 일정 관리의 받은 일정을 **화면 미리보기**로 구분해 보여 준다.
3. 마음결 AI의 v4 분석에서 오프라인 설명, 고정된 합성 계정·인맥·프로필로 추천을 실행한다.
4. 프리셋 선택 후 예산을 수정하고 다시 계산해 예산 반영과 근거를 보여 준다. 프로필/시나리오 조건 변경 시 보류되는 흐름도 확인한다.

프로필은 SQLite에 남기 때문에 촬영 전 가상 계정·직업·동의·시나리오 상태를 다시 확인한다. 원본 DB나 사용자 기록을 삭제해 초기화하지 않는다. 실제 발송은 수행하지 않는다.

## 미래의 일정 발송 연결 범위

지인이 보내 준 일정에는 발신자·수신자·원본 일정 ID·공유 범위·수신 시각·일정 변경/취소 상태가 필요하다. 본인 달력에 추가할 때는 명시적인 동작과 중복 방지가 필요하다. 일괄 발송은 대상 인맥 미리보기·발송 확인·결과/실패 상태를 별도로 설계한다. 이번에는 이 송수신 기능을 구현하지 않는다.

공유 부고는 일정 상단이 아닌 **상단 알림함 → 공유 소식**에서 카드로 확인한다. 친구 요청은 인맥 관리의 받은 요청, 직접 수신할 초대는 일정 관리의 받은 일정으로 구분한다.
