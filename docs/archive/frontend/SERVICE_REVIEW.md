# 실제 서비스 전환을 위한 점검 제안

이번 요청의 인맥 검색·가입 항목·예절 안내·CSV 배치만 구현했습니다. 아래 사항은 현재 코드와 화면을 점검해 제안하는 후속 작업이며 **이번에는 구현하지 않았습니다.**

| 우선순위 | 현재 확인한 점 | 제안 |
| --- | --- | --- |
| 출시 전 | 계정과 인맥·일정·장부가 브라우저 저장이며, 체험 계정 사이에도 데이터를 공유함 | 서버 인증·계정별 DB 소유권 검사·세션 만료·로그아웃 시 상태 초기화를 먼저 연결 |
| 출시 전 | 새 전화번호·이메일은 형식만 검사하며 실제 소유 여부는 확인하지 않음 | 아이디 중복 확인 API, 이메일/전화번호 인증, 비밀번호 재설정·로그인 시도 제한 설계 |
| 출시 전 | 가입 시 이름·전화번호·이메일이 수집됨 | 각 항목의 이용 목적과 필수 여부를 결정하고 개인정보 처리 안내·보관 기간·탈퇴/삭제 절차 정리. 브라우저 체험 입력을 실제 서버 가입으로 자동 이전하지 않기 |
| 출시 전 | 서버 AI는 가상 인맥과 가상 장부를 참고하고 일반 CRUD는 브라우저 데이터를 사용함 | 실제 DB 연결 시 같은 사용자·인맥·행사 ID를 공유하고 응답에 참조 기록 ID·기준 시각을 함께 제공. 근거 없는 금액을 사실처럼 제시하지 않는 평가 진행 |
| 높음 | 기존 홈·AI·통계에 7~10px 보조 문구가 여러 곳 있음 | 본문 14~16px 수준과 충분한 행간을 기준으로 확대하고, 200% 화면 확대·긴 이름·작은 모바일에서 잘림 점검 |
| 높음 | 관리 아이콘 일부가 33px 안팎이고, 여러 필터·화면 상태를 색으로 주로 구분함 | 터치 영역을 44px 안팎으로 확보하고 선택 상태의 글자/아이콘도 병행. 키보드 순서·포커스·스크린리더 이름·명도 대비를 실제 보조공학으로 점검 |
| 높음 | 기록 삭제는 확인 후 즉시 영구 제거되는 로컬 방식임 | 실행 취소 또는 복구함, 변경 이력, 서버 저장 실패 시 복구를 추가. 가져오기 전 백업 안내와 계정별 내보내기 범위 명확화 |
| 높음 | 알림은 페이지가 열린 동안 동작하고 발송 이력도 브라우저에 있음 | 서버 예약 작업·Web Push·기기 구독·중복 발송 방지·조용한 시간·알림 테스트 발송을 설계 |
| 보통 | 새 일정 유형은 결혼식·장례식·돌잔치·생일의 4개, 예절은 환갑·칠순·팔순도 안내함 | 행사 유형을 설정에서 확장하거나 어른 생신으로 묶어 관리할지 결정. 음력/반복 일정과 날짜 계산 정책을 별도로 정의 |
| 보통 | 검색과 장부 필터는 페이지를 나갔다 돌아오면 초기화됨 | 마지막 필터/정렬 유지, 월 이동 후 오늘로 복귀, 검색 지우기, 빈 화면의 다음 행동 안내를 일관되게 구성 |
| 보통 | 예절은 정적 체크리스트이고 AI는 별도 기능임 | 검토일·편집 담당·자료 출처를 관리하고, 일정 상세에서 해당 유형 예절로 이동하는 연결을 추가하는 방안 검토 |

권장 순서는 **계정/DB/개인정보 → 기록 복구/알림 신뢰성 → 작은 글자/터치/키보드 검증 → 반복 일정 등 편의 기능**입니다. 개인정보·인증 관련 최종 운영 정책은 담당자와 별도로 확정해야 합니다.
