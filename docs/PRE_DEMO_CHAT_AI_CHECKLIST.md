# 시연 전 채팅·AI 품질 점검 (계정 데이터 작업 제외)

> 기준: `develop`의 2026-10-31 병합 상태에서 출발. 계정·친구 관계·시드 데이터 수정은 다른 작업에서 진행한다.
> 이 문서는 녹화·실기기 테스트 완료 보고가 아니라 실제 점검 절차다.

## 점검 범위

- 로그인 전: AI 질문 입력창과 예시 질문이 비활성화되고 상단 계정 메뉴의 로그인 안내가 표시되는지 확인한다. 세션 없이 채팅 API를 호출하면 인증이 거부되어야 한다.
- 로그인 후: 질문 전송 즉시 사용자 질문과 `답변 생성 중`이 표시되는지, 전송 중 중복 전송이 차단되는지 확인한다.
- 성공·오류·중단: 기다림 표시가 사라지고 입력 상태가 복구되는지 확인한다. 브라우저 중단은 서버 작업 중단을 보장하지 않으므로 기록 저장 여부를 확인한다.
- 금액 상담: 추천액을 최상단에 보이고 계산·통계·근거는 `추천 계산·통계·근거 자세히 보기`에서만 기본 표시하는지 확인한다. 직접 평균·합계를 질문하면 상세 정보를 열어 실제 DB 수치와 대조한다.
- 모델 판단: 식사 여부의 구조화된 LLM 분류 결과가 있으면 정규식보다 우선한다. 한 상담 요청의 질문 분류와 답변 생성은 **총 30초**의 모델 호출 예산을 공유하며, 주 모델 `claude-opus-4-8`은 최대 20초, 보조 모델 `gpt-5.4-mini`는 최대 10초다. 실제 API 연결 시 보조 모델 ID 지원 여부와 왕복 시간을 확인한다. HTTP 통신의 단계별 타임아웃이므로 전체 브라우저 응답을 30초 정각에 강제 중단하는 보장은 아니다.
- 기존 사례: `docs/TEST1234_DEMO_SCENARIOS.md`의 검토 03·05·15·17은 다른 계정 수정이 완료된 뒤 표현만 재확인한다. 이번 작업에서 계정 데이터는 변경하지 않는다.

## 동일 입력의 AI 유무 비교

정책·금액 추천 엔진과 LLM 설명의 역할을 구분하기 위해, 기존 합성 `U001`의 지인·예산·식사 조건을 고정한 뒤 동일한 `ChatService.chat` 요청을 두 번 실행한다. 이 비교는 회원 시연 계정이나 개인 장부를 변경하지 않는다.

```sh
python -m scripts.compare_ai_recommendation
```

첫 번째 결과는 키가 비어 있는 모델 게이트웨이의 **정책·추천 엔진 기준선**이다. 두 번째 결과는 현재 서버에 설정된 Codyssey 키와 실제 모델 호출을 사용한다. 실행 시 비밀 키를 표준 출력에 기록하지 않는다.

- `not_configured` 또는 `unavailable`이면 실제 AI 설명 미실행이다. 모델을 실행한 것처럼 소개하지 않는다.
- 양쪽의 추천 금액·법률 판정이 같은지 확인한다. 서로 다르면 시연을 중단하고 원인을 조사한다.
- 다른 부분은 자연어 맥락 해석의 구체성, 모호한 사실의 처리, 추가로 확인할 행동 등 **설명의 질**이다. 주관적 품질과 향상률을 정량 검증 없이 주장하지 않는다.
- 이 명령은 프런트엔드 UI에서 모델을 켜고 끄는 기능이 아니다. 비교용 개발·발표 증거다.

## 자동·수동 검사

```sh
python -m pytest -q tests/test_ai.py tests/test_chat_unified_engine.py tests/test_demo_test_account.py
cd frontend
corepack pnpm test
corepack pnpm build
```

발표 녹화는 실행 중인 서버·브라우저로 수동 진행한다. 권장 장면은 비로그인 제한, 일반 상담 진행 표시, 예산 상한과 추천 이유, 통계 상세 영역, 법적 위험 보류, AI 유무 비교 순서다. 화면에 API 키·실제 개인정보·세션 값이 표시되지 않도록 한다.

시연 완료 체크: 실제 서버 호출 상태 / 오류·중단 복귀 / 추천 금액 불변 / 기존 20개 회귀 / 실제 모델 사용 여부 / 녹화본 재생. 실행하지 않은 항목은 `NOT_RUN`으로 남긴다.
