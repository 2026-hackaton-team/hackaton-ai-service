# 인맥·일정·장부 SQLite 단일 원천

> 해커톤 로컬 시연용 계약입니다. 일반 로그인 ID는 서버의 합성 사용자 ID에 자동 연결되며, React의 인맥·일정·장부와 AI 자유 상담은 같은 SQLite 작업공간을 참조합니다. 대화 이력·공유 소식·로그인 계정·친구 관계는 아직 별도 저장소에 남습니다.

## 사용 방법

1. 서버와 프런트를 함께 실행하고 일반 계정으로 로그인합니다. 별도 AI 가상 계정을 선택하지 않습니다. 기존 `test1234`·`demo_seojin` 계정은 서버의 시연 사용자 ID를 재사용하고, 새 시연 계정은 고정된 독립 작업공간 ID를 받습니다.
2. 서버 작업공간이 아직 초기화되지 않았다면 모든 화면 상단에서 **기존 브라우저 기록 서버로 이전** 또는 **빈 서버 공간 시작** 중 하나를 선택합니다. 이미 초기화된 계정은 기존 기록을 그대로 사용합니다.
3. 브라우저 기록 이전 전 서버는 ID 및 연결 관계를 검증합니다. 저장은 버전 조건에 따른 하나의 SQLite 트랜잭션으로 완료됩니다. 실패하면 기존 브라우저 기록을 삭제하거나 수정하지 않습니다.
4. 초기화 이후 인맥·일정·장부 조회와 편집·CSV 가져오기·삭제는 서버를 기준으로 합니다. 서버 저장이 성공한 뒤에만 화면 상태가 갱신됩니다.
5. 같은 로그인 계정으로 다시 접속하면 서버에 저장된 데이터를 읽습니다. 서버 충돌(HTTP 409) 시 최신 상태를 다시 조회하고 실패한 저장은 자동 재적용하지 않습니다.

## API와 계산 경로

- `POST /api/demo/accounts/resolve`: 로그인 ID를 시연 사용자 ID로 연결 (`test1234` → `TEST1234`, 미등록 시 `LOCAL_` 접두 ID)
- `GET /api/workspace/personal`: 로그인 계정의 현재 서버 인맥·일정·장부 및 버전 조회
- `POST /api/workspace/migrations/preview`: 이전 대상의 유효성·버전 확인, 저장하지 않음
- `PUT /api/workspace/personal`: 동일 버전의 전체 자료를 원자적으로 교체
- `POST /api/conversations/{conversation_id}/messages`: 실제 자유 상담은 위 작업공간을 변환한 개인화 데이터로 추천 엔진을 호출함
- 법률·관계 합성 시나리오(`가상 시나리오`)는 시연용 고정 데이터로 분리되어 있습니다.

친밀도(`closeness_score`, 1~5점 또는 미기록)와 중요도(`importance`)는 **서로 다른 속성**입니다. 중요도를 임의의 친밀도 점수로 변환하지 않습니다. '특별히 챙길 사람'(`special`)도 서버에 저장되어 개인화 참고 요인으로 전달됩니다. 지급·수령 거래는 인물 ID와 행사 ID를 명시적으로 연결하며, 추천 엔진은 관련 거래 내역과 예산·RAG·법률 정책을 별도로 적용합니다. 본인 행사에는 허구의 상대방을 보이지 않게 하는 내부 참조 ID를 사용합니다.

## 제약·안전

- 프런트의 브라우저 `localStorage` 기록은 **기존 자료의 읽기·이전용 백업**으로 남습니다. 선택된 서버 계정에 수정 내용을 자동 복사하지 않습니다.
- 로그인하지 않은 상태에서는 서버 개인 기록을 저장할 수 없습니다. 시연 중 서로 다른 로그인 계정으로 데이터를 이전하지 않도록 확인해야 합니다.
- 로그인은 브라우저 저장 계정이며 `X-Demo-User-Id`와 계정 연결 API는 보안 인증이 아닙니다. 실제 개인정보·실제 금액을 입력하거나 외부에 서버를 공개하지 마세요.
- 가상 계정을 초기화하면 해당 계정의 개인 합성 데이터는 일반 자유 상담에서 서버 작업공간 데이터로 대체됩니다. 고정 시나리오는 별도 실행됩니다.
- 공개 부고·친구 요청·로컬 로그인 및 사회관계 데이터까지 하나의 물리 DB로 통합한 것은 아닙니다. 친구/공유 데이터의 서버 이전은 별도 후속 작업입니다.

## 검증

`python -m pytest -q tests/test_workspace_single_source.py tests/test_demo_login_identity.py`와 `cd frontend && corepack pnpm test && corepack pnpm build`를 실행합니다. 409 충돌, 다른 계정 접근, 잘못된 행사 연결, 1~5점 범위, 본인 행사, 거래 누락을 검사합니다. 최종 Windows/macOS 브라우저 E2E 및 실제 Codyssey LLM 호출은 별도로 확인해야 합니다.
