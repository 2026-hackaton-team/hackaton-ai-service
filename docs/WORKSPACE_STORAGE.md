# 개인 작업공간 SQLite 통합 및 이전

## 범위
AI 추천 엔진, LLM, RAG의 계산 경로는 수정하지 않는다. 이 변경은 React 인맥·행사·장부 데이터를 계정별 SQLite에 보존하고 다음 작업에서 같은 원천을 참조할 수 있도록 API를 제공한다.

## API와 데이터 원천
- `GET /api/workspace/personal`: 현재 가상 계정의 인맥·행사·장부, 버전, 초기화 여부
- `POST /api/workspace/migrations/preview`: 이전 입력의 타입·참조 관계·현재 버전 확인(실제 저장 없음)
- `PUT /api/workspace/personal`: `revision`이 동일할 때 SQLite 트랜잭션으로 전체 자료 교체
- 기존 `GET /api/workspace`: 합성 JSON을 읽는 시연용 API를 유지한다.

SQLite 파일명은 기본적으로 `data/demo_workspace.sqlite3`이다. 테스트에서는 `GYEONGJOSA_WORKSPACE_DB`로 저장 위치를 격리한다.

현재 로컬 시연은 `X-Demo-User-Id`로 가상 계정을 선택한다. 이 헤더는 실제 회원 인증이 아니므로 네트워크에 공개하지 않는다.

## 기존 브라우저 기록 보존

1. React의 일정 화면 또는 AI 화면에서 가상 계정을 선택한다.
2. 해당 가상 계정의 서버 작업 공간이 비어 있으면 **브라우저 기록을 서버로 이전** 또는 **빈 기록으로 시작** 중 하나를 선택한다.
3. 이전 버튼은 브라우저의 기존 인맥·행사·장부 기록을 읽어 서버에서 연결 관계와 버전 검증을 수행한 다음 원자적으로 기록한다.
4. 이전 중 오류가 발생하면 기존 브라우저 데이터를 삭제하거나 변경하지 않는다. 저장이 성공해도 기존 브라우저 기록은 보관한다.
5. 한 번 초기화된 계정에는 초기 이전 버튼을 다시 표시하지 않는다. 최신 서버 데이터는 사용자 계정 선택과 재접속 때마다 조회한다.

가상 계정을 선택하지 않은 과거 브라우저 단독 모드는 이전 기록 확인 용도로 남아 있다. **서버 통합 사용을 위해서는 반드시 가상 계정을 먼저 선택해야 한다.** 서로 다른 가상 계정에 동일한 브라우저 기록을 이전하지 않도록 이전 대상 계정을 확인한다.

기존 프론트 `p1` 인물과 AI 합성 데이터 `P001` 인물은 이름이 같더라도 자동 결합하지 않는다. 중요도는 친밀도 1~5점으로 임의 변환하지 않는다.

## 변경 검증
- 소유자 계정별 별도 조회·쓰기
- 인물/행사/거래 ID 중복과 잘못된 참조 거부
- 저장 실패 및 버전 409 충돌 시 기존 데이터 유지
- CSV 가져오기·장부 수정·삭제·행사 삭제의 원자 저장
- Python 테스트와 React 테스트·빌드
- 실제 Windows/macOS 브라우저 조작은 별도의 E2E 검증 대상

## 후속 추천 엔진과의 연결 경계
현재 `gyeongjosa_ai/data.py`와 `app/recommender.py`의 합성 데이터 조회 동작은 그대로이다. 이 작업은 SQLite 개인 작업공간을 AI의 새 단일 데이터 조회 경로로 바꾸지 않는다. 추천 엔진 측 변경과 통합할 때는 가상 계정 소유자, 명시된 인물 ID 매핑, 행사 유형/금액 방향 변환, 합성 시연 격리를 확인해야 한다.
