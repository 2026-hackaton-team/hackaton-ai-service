# 김시나리오 20인 실제 AI 추천 검증 설계

## 목적 및 범위

김시나리오 전용 가상 계정에 서로 다른 상황의 지인 20명, 거래·일정 기록을 서버 SQLite에 저장한다. AI 추천 결과는 기존 일반 자유 상담 경로로만 계산한다. 기존 고정 v4 시나리오/대화/데이터와 일반 사용자 기록은 변경하지 않는다.

## 주요 설계 결정

1. **데이터**: `data/kim_scenario_cases.json`에 허구의 지인·질문·예산·양방향 금액 이력 및 검증 초점만 기록한다. 추천액과 LLM 답변을 미리 넣지 않는다.
2. **서버 단일 원천**: `gyeongjosa_ai/scenario_lab.py`에서 전용 계정 `SCENARIO_KIM`의 SQLite 초기 데이터를 구성한다. 최초 서비스 초기화 시 작업공간이 비어 있을 때만 저장하며 기존 버전은 절대 덮어쓰지 않는다. 장부의 인물·행사·금액 참조는 기존 `WorkspaceInput` 검증을 사용한다.
3. **데이터 접근**: 서버의 일반 대화 API는 각 질문마다 `data_for_chat`을 통해 최신 저장 장부를 읽는다. 타 계정은 다른 계정의 지인/이력에 접근하지 못한다. 데이터는 가상 시연 목적이며 계정 선택은 인증이 아니다.
4. **추천**: `/api/conversations/{id}/messages` → `ChatService.chat_auto` → 기존 개인화·RAG·법률 엔진을 따른다. 법률 위험/추가 질문은 그대로 출력하고, LLM이 금액을 변경하지 못하도록 기존 서버 결과를 우선한다.
5. **검증 화면**: 기존 AI 자유 상담에서 김시나리오를 선택하면 20개 질문 목록과 인물 선택을 보여준다. 선택 1건 또는 전체 20건을 새 대화별로 **순차** 실행하며 각각 실제 요청·결과를 보존한다. 추천액·예산·AI 모델·RAG 출처·조정 근거·오류를 함께 표시한다.
6. **응답 설명**: 기존 추천 금액을 변경하지 않고, 거래 이력이 존재해도 모델의 검증된 자연어 설명을 함께 제공한다.

## 검증 조건

- 20명 고유 인물 ID와 최소 1개 이상의 무이력 사례가 존재한다.
- SQLite 최초 시드 후 같은 계정 사용자 수정은 보존되고, 타 계정의 장부는 변경되지 않는다.
- 실시간 일반 대화 API 20개 질문 호출을 모의 모델과 실제 추천 엔진으로 검사한다. 모델이 조작한 추천 금액은 채택하지 않는다.
- 모든 금액은 사례 예산 상한 이내이며, 금액이 보류되거나 확인이 필요하면 그대로 표시한다.
- 동명이인 구분 없이 서로의 기록을 합산하지 않는다.
- 테스트에서 외부 LLM 실제 호출 여부와 실서비스 브라우저 E2E는 별도로 구분한다.

## 알려진 한계

- 합성 인맥의 직무·공직자 여부는 본인 인증/상대 공개 동의로 검증된 정보가 아니다. 의심 신호는 법률 검토를 유도하지만 금액 허용을 확정하지 않는다.
- 참석 불균형과 비금전적 지원의 정량 가중치는 현재 기존 추천 엔진의 입력으로 확정되지 않는다. 결과 비교에서 해당 미지원 신호를 밝혀야 하며 가짜 조정 금액을 만들면 안 된다.
- AI 분류/해석은 외부 모델 설정이 필요하다. 모델 실패는 오류로 보고하고 오프라인 합성 성공 결과로 대체하지 않는다.
- 현재 검증 실행은 UI에서 20개 API 요청을 순차적으로 수행한다. 대량 실행 시 모델 사용량이 발생한다.
