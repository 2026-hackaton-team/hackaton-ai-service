# 김시나리오 20인 실제 AI 추천 검증 설계

## 목적 및 범위

김시나리오 전용 가상 계정에 서로 다른 상황의 지인 20명, 거래·일정 기록을 서버 SQLite에 저장한다. AI 추천 결과는 기존 일반 자유 상담 경로로만 계산한다. 기존 고정 v4 시나리오/대화/데이터와 일반 사용자 기록은 변경하지 않는다.

## 주요 설계 결정

1. **데이터**: `data/kim_scenario_cases.json`에 허구의 지인·질문·예산·양방향 금액 이력 및 검증 초점만 기록한다. 추천액과 LLM 답변을 미리 넣지 않는다.
2. **서버 단일 원천**: `gyeongjosa_ai/scenario_lab.py`에서 전용 계정 `SCENARIO_KIM`의 SQLite 초기 데이터를 구성한다. 최초 서비스 초기화 시 작업공간이 비어 있을 때만 저장하며 기존 버전은 절대 덮어쓰지 않는다. 장부의 인물·행사·금액 참조는 기존 `WorkspaceInput` 검증을 사용한다.
3. **데이터 접근**: 서버의 일반 대화 API는 각 질문마다 `data_for_chat`을 통해 최신 저장 장부를 읽는다. 타 계정은 다른 계정의 지인/이력에 접근하지 못한다. 데이터는 가상 시연 목적이며 계정 선택은 인증이 아니다.
4. **추천**: `/api/conversations/{id}/messages` → `ChatService.chat_auto` → 기존 개인화·RAG·법률 엔진을 따른다. 법률 위험/추가 질문은 그대로 출력하고, LLM이 금액을 변경하지 못하도록 기존 서버 결과를 우선한다.
5. **검증 화면**: 기존 AI 자유 상담에서 김시나리오를 선택하면 20개 질문 목록과 인물 선택을 보여준다. 선택 1건 또는 전체 20건을 새 대화별로 **순차** 실행하며 각각 실제 요청·결과를 보존한다. 추천액·예산·AI 모델·RAG 출처·조정 근거·오류를 함께 표시한다.
6. **응답 설명**: 거래 이력이 있는 경우 서버에서 확인한 거래·예산·관계 조정 근거를 표시하고, 모델이 만들어 낸 사건 사실 서술로 이를 덮어쓰지 않는다.

## 금액 통계 표시

- 일반 AI 금액 상담과 김시나리오 검증 결과에 **내가 낸/받은 건별 평균·중앙값·합계·최근 기록**을 동일하게 표시한다.
- 금액은 질문 문장에서 재구성하지 않고 서버의 **선택한 인물 SQLite 장부**를 조회한 뒤 계산한다. 명시적 0원 기록은 실제 거래액 평균에 포함하지 않는다.
- 이전 양수 기록이 2건 이상 있고 최신 거래가 이전 기록 중앙값의 **2배 이상**이면 최근 급증 신호를 표시한다. 이는 비정상 가능성을 살펴보라는 참고 정보이며 통계적으로 입증된 이상치가 아니다.
- 양수 거래가 없으면 평균을 만들지 않고 기록 없음으로 표시한다. 거래 1건만으로 급증을 판정하지 않는다.
- 급증 정보는 설명과 검증에만 사용하며 현재 개인화 추천 엔진의 후보 금액·예산 상한·법률 보류 판정을 덮어쓰지 않는다.
- 실거래가 있는데 통계가 반환되지 않거나 최근 고액 사례에 급증 근거가 없으면 PASS가 아닌 REVIEW로 남긴다.

## 예산과 추천액 비교

- 예산은 목표 지출액이 아니라 초과할 수 없는 상한이다. 예산보다 낮은 추천액만으로 추천 오류를 판단하지 않는다.
- 개인화·법률 추천 엔진은 기존 후보 `30,000 / 50,000 / 70,000 / 100,000 / 150,000 / 200,000원`을 유지한다.
- 기존 엔진의 `unrestricted_amount_krw`는 동일 거래·관계 근거에서 **예산 제한만 제외했을 때** 선택하는 후보이며 실제 송금 권고액이 아니다.
- 이 후보가 예산을 넘으면 `budget_limited=true`로 기록한다. 실제 추천액이 예산보다 작더라도 금액 후보 단계 때문에 제한이 작용할 수 있다.
- 선택액이 예산과 같다는 사실만으로 상한 때문에 낮췄다고 단정하지 않는다.
- 일반 AI 대화와 김시나리오 검증 화면에서 예산·선택액·차액·예산 사용률·상한 제한 작용 여부·관계 조정 근거를 함께 보여준다.
- 법률 위험으로 금액을 보류하면 차액과 예산 미적용 후보를 노출하지 않는다. 법률 사실이 불명확한 비교 참고액은 행동 가능한 추천액과 분명히 구분한다.
- 검증 UI는 **예산보다 적음 / 예산과 같음 / 상한 제한 작용 / 금액 보류** 사례로 필터링할 수 있다.
- 기존 모델 호출과 추천 금액 산출은 변경하지 않고 설명용 데이터만 추가한다.

## 검증 조건

- 20명 고유 인물 ID와 최소 1개 이상의 무이력 사례가 존재한다.
- SQLite 최초 시드 후 같은 계정 사용자 수정은 보존되고, 타 계정의 장부는 변경되지 않는다.
- 실시간 일반 대화 API 20개 질문 호출을 모의 모델과 실제 추천 엔진으로 검사한다. 모델이 조작한 추천 금액은 채택하지 않는다.
- 모든 금액은 사례 예산 상한 이내이며, 금액이 보류되거나 확인이 필요하면 그대로 표시한다.
- 동명이인 구분 없이 서로의 기록을 합산하지 않는다.
- 테스트에서 외부 LLM 실제 호출 여부와 실서비스 브라우저 E2E는 별도로 구분한다.

## AI 응답 평가 절차

- 김시나리오 프로필에서 개별 또는 20건 순차 실행을 선택한다. 실제 LLM API 설정과 비용이 필요하며, 자동 테스트의 대역 응답을 실제 모델 성능으로 해석하지 않는다.
- 검증 화면에서 인물 ID 일치, 예산 상한, 서버 추천 엔진 금액 일치, 관계 조정 신호, 직무 위험 사례 금액 보류 여부를 점검한다.
- PASS는 검사 가능한 계약을 충족했다는 뜻이다. 금액의 사회적 적정성이나 법적 적법성을 인증하지 않는다.
- REVIEW는 추가 정보 요청, LLM 설명 미완료, 기대한 관계 조정 근거 누락을 뜻하며 자동 합격이 아니다.
- FAIL은 API 오류, 인물 혼동, 예산 초과, 금액 불일치, 위험 사례 금액 제시 등 명시적인 위반이다.
- 결과 화면의 `결과 JSON 저장`을 통해 질문·모델·원본 결과·판정을 저장하고 사례별로 비교한다. API 키는 결과 파일에 포함되지 않는다.
- 실제 모델 실호출 20건을 별도로 수행하지 않은 상태에서는 외부 모델 E2E를 PASS로 기록하지 않는다.

## 알려진 한계

- 합성 인맥의 직무·공직자 여부는 본인 인증/상대 공개 동의로 검증된 정보가 아니다. 의심 신호는 법률 검토를 유도하지만 금액 허용을 확정하지 않는다.
- 참석 불균형과 비금전적 지원의 정량 가중치는 현재 기존 추천 엔진의 입력으로 확정되지 않는다. 결과 비교에서 해당 미지원 신호를 밝혀야 하며 가짜 조정 금액을 만들면 안 된다.
- AI 분류/해석은 외부 모델 설정이 필요하다. 모델 실패는 오류로 보고하고 오프라인 합성 성공 결과로 대체하지 않는다.
- 현재 검증 실행은 UI에서 20개 API 요청을 순차적으로 수행한다. 대량 실행 시 모델 사용량이 발생한다.
