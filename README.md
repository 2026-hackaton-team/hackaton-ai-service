# 온마음 — 경조사 AI 추천 · 직무 관련성 검토 (통합 발표 시연)

> **48시간 해커톤 로컬 시연 프로젝트.** 이 문서는 GitHub `feat/integrate-rag-react` 브랜치의 **React + FastAPI + 온마음 v4 RAG 통합 버전**을 설명합니다. `main`/기존 `develop`의 출시 상태와 다릅니다.

**한 줄 소개:** 경조사 금액만 답하는 AI가 아니라 **예산·관계 이력·공개 근거를 분리해 추천하고, 직업·계약·심사 이해관계가 의심되면 금액 추천을 보류하며 추가 사실을 확인하는 도우미**입니다.

[최종 발표 대본·실습 시나리오](docs/PRESENTATION_DEMO.md) · [상세 개발/미완료 상태](INTEGRATION_STATUS.md) · [통합 PR #3](https://github.com/2026-hackaton-team/hackaton-ai-service/pull/3)

## 발표 전에: 3가지 기능

1. **마음 AI 자유 상담** — 가상 계정 선택 후 자연어로 이력·예산·참석·부고 질문. 서버에 계정별 대화가 저장됩니다. *실제 Codyssey LLM 키 및 네트워크가 필요하며, 실패 시 AI 답변을 모의 생성하지 않습니다.*
2. **온마음 v4 직무·법적 위험 분석** — 사용자 직업·담당 업무 + 동의된 상대 직업 범주 + 자유서술 관계 단서를 결합합니다. RAG 근거/조건/예산으로 추천·추가 질문·송금 보류를 구분합니다. **오프라인 설명만**으로 결정적 데모가 가능합니다.
3. **공유된 부고 추천** — 친구 또는 친구의 친구 관계에서 명시적으로 공유·참석 허용된 장례 소식만 보입니다. 같은 이름이라는 이유만으로 지인과 자동 결합하지 않습니다.

## 1. 실행 (Windows 로컬)

**조건:** Python 3.12, Node.js, `pnpm`, 통합 브랜치 소스. Windows의 `Documents\Codex\proto_rag_llm` **단독 v4** 폴더와 이 GitHub 통합 저장소는 별개입니다.

**터미널 1 — 저장소 루트:**

```powershell
git switch feat/integrate-rag-react
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt "openai>=1.75,<3"
.\.venv\Scripts\python.exe -m uvicorn gyeongjosa_ai.api:app --host 127.0.0.1 --port 8000
```

**터미널 2 — 같은 저장소의 `frontend/` 폴더:**

```powershell
cd frontend
corepack enable
pnpm install --frozen-lockfile
pnpm dev
```

브라우저 **http://127.0.0.1:5173** → **마음 AI** 메뉴 → `AI 자유 상담` 또는 `v4 직무·법적 위험 분석` 선택.

| 경로 | 목적 |
|---|---|
| `http://127.0.0.1:8000/api/health` | 통합 API 상태 (`status=ok`) |
| `http://127.0.0.1:8000/v4/api/health` | v4 RAG 상태 (`policy_engine=v4`) |
| `http://127.0.0.1:8000/v4/` | v4 원본 분석 UI 직접 접근 |
| `http://127.0.0.1:8000/v4/api/docs` | v4 API 문서 |
| `http://127.0.0.1:5173` | 최종 통합 React UI |

**주의:** `pnpm dev:demo`는 별도의 프론트 모의 백엔드를 실행합니다. 통합 시연에는 `pnpm dev`만 사용하세요. 이미 8000 포트를 쓰는 다른 서버가 있으면 먼저 해당 서버를 정상 종료하세요.

Codyssey 모델이 필요한 경우 **서버 프로세스의 `CODYSSEY_API_KEY`** 설정이 필요합니다. v4의 선택형 외부 관계 분석은 별도 `OPENAI_API_KEY`와 명시 동의가 있어야 호출합니다. 두 키는 목적과 API가 다릅니다. 키를 GitHub·화면·로그에 노출하지 마세요. **v4 오프라인 시연에는 키가 필요 없습니다.**

## 2. 권장 8분 발표 흐름

상세 조작은 반드시 **[발표용 데모 운영서](docs/PRESENTATION_DEMO.md)**를 참조하세요.

| 장면 | 실제 조작 | 검증할 포인트 |
|---|---|---|
| 문제 소개 | 일정·인맥·금액 메뉴 소개 | 기존 React UI 보존 |
| 자연어 상담 | 마음 AI → `U001` 선택, 합성 질문 | 자유 질문·이력·추가 질문 구조. *실모델 키 필요* |
| 소식 발견 | 일정 관리 → 공유 부고 카드 | 공유 범위와 관계 조건 |
| 예산 배려 | v4 → `직장 동료 결혼식` 프리셋 → 예산 `30000`으로 변경해 **다시 제출** | 추천액은 3만원 초과 금지; 후보 없으면 금전 추천 없음 |
| 법적 조건 | v4 → `공직자 부조 예외 (가정)` | 공식 자료 검증 후 **조건부 5만원** 재평가 |
| 위험 탐지 | v4 → `계약 심사 이해충돌 (가정)` | 거래 위험 시 금액 보류 |
| 양방향 분석 | `U001`의 직업/담당업무를 공무원·계약업무로 등록 → 자연어 “저는 시청 계약 담당자이고 상대방은 제가 심사하는 거래처 직원입니다” → 미확인/확인 비교 | 사실과 추측 분리·기관 규정 검토 |
| 근거 투명성 | 적용 근거/제외 근거·RAG 검색 결과 확인 | 왜 계산했거나 보류했는지 추적 |

**주의 1:** 프리셋을 누르면 예산을 초기화하므로 **먼저 프리셋 → 예산 수정 → 재제출** 순서로 진행하세요.

**주의 2:** v4의 가상 법적 시나리오는 `scenario_id != default`일 때 명시된 합성 가정을 사용합니다. 실제 본인·상대의 직업 정보를 반영하는 장면에서는 **`default`로 되돌리세요.**

**주의 3:** v4 화면의 `AI 설명 방식`은 **오프라인 설명만**, `외부 LLM 분석 동의`는 **해제**하면 인터넷 없이 법률 근거·예산·자연어 단서의 결정적 시연이 가능합니다.

## 3. 핵심 설계 / 데이터 계약

```text
React (frontend/) ── /api/* ─── FastAPI (gyeongjosa_ai) ── 가상 계정/대화 SQLite + 합성 데이터
       └──────────── /v4/* ── v4 FastAPI (app/) ── 프로필 SQLite + 근거 TF-IDF + 정책/추천
```

- v4는 공개 자료를 수동 재서술한 소규모 지식베이스를 **한국어 문자 n-그램 TF-IDF**로 검색합니다. 벡터 DB나 실시간 법령 수집은 아직 없습니다.
- 추천액은 확인된 예산을 넘지 않으며, 법적 확인이 부족할 때는 `NEEDS_FACTS` / `NEEDS_EXPERT_REVIEW` 등의 **보류 상태**가 가능합니다. 일반 참고액과 실제 송금 추천액을 구분합니다.
- 상대 직업 분류는 **친구 연결·추천 목적 이용 허용·공개 범위**가 모두 충족된 경우에만 서버 정책에 사용합니다. 자기신고 직업만으로 실제 신분이나 적법성을 보증하지 않습니다.
- v4 자연어 관계 입력은 해당 API 처리 시 프로필 DB에 저장하지 않으며, 외부 LLM 전송은 선택적 동의가 필요합니다. **자유 상담 채팅은 대화 본문을 서버에 저장하므로 실제 개인·직무 민감정보를 입력하지 마세요.**
- 부고와 AI 자유 상담은 다른 합성 시연 데이터 범위를 사용합니다. **React 전체 CRUD가 아직 하나의 DB로 통합된 것은 아닙니다.**

## 5. 개인정보·법적 고지

**모든 사람·기관·거래는 시연용 합성 데이터입니다.** 외부 공개 서비스를 목적으로 하지 않으며 실사용 데이터/실제 개인정보는 입력하지 않습니다. 직업은 자기신고이며 신분 인증은 없습니다. 특히 청탁금지법상 조건부 현금 경조사비 **5만원 기준은 무조건적인 허용 금액이 아닙니다.** 예외 요건과 직무 관련성에 따라 금액이 적어도 허용되지 않을 수 있습니다.
