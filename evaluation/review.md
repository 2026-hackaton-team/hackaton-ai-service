# 실제 모델 비교 및 검토 기록

모든 질문과 기록은 가상 데이터다. 아래는 코디세이 게이트웨이로 호출한 결과와 그 후의 코드 변경을 구분한 기록이다. 한 번씩 실행한 소수의 사례이므로 실제 사용자에 대한 정확도나 통계적 성능으로 해석하지 않는다.

## 호출 예산

2026-11-01 현재 사용자가 **총 500회**로 검증 호출 예산을 상향했다. 이미 기록된 예약 5회·평가 57회(총 62회)는 유지했으며 기록상 잔여 상한은 **438회**다. 아래 내용은 과거 50회와 62회 단계의 실제 검증 이력이다. 현재 공급자 쿼터는 별도로 확인해야 한다.

- 앞선 연결 오류·중단 시도와 모델 연결 확인을 보수적으로 5회로 예약했다.
- 최초 비교 34회, 보완 후 재검증 10회, Opus 금액 답변 재확인 1회를 사용해 처음 허용된 50회에 도달했다.
- 이후 사용자가 두 모델의 이력·금액·참석을 다시 확인하도록 최대 12회를 추가로 허용했고, 12회를 사용했다.
- `budget.json` 기준 **예약 5회 + 평가 57회 = 최대 62회**다. 중단된 요청의 실제 전송 여부가 불명확하므로 보수적으로 계산했다.
- 데이터 생성에는 코디세이 API를 호출하지 않았다.

## 보완 후 재검증

- 거래 기반 이력·금액 답변은 관련 거래 ID를 인용하도록 검증했다. GPT-5.4의 금액 사례는 `T001`, `T002`를 인용하고 예산 안의 선택지를 반환했다.
- Opus의 금액 사례는 본문에 금액이 들어가 당시 형식 검사에서 실패했다. 이후 확인된 금액만 검증하고 본문의 금액을 제거해 근거 카드와 선택지에 표시하도록 수정했다.
- 두 모델의 참석 조언에는 행사 기간과 실제 조문 가능 시간을 혼동할 여지가 있는 표현이 있었다. 이후 프롬프트에서 두 정보를 구별하도록 보완했다.
- 개인 금액 이력이 없는 경우 구체적인 금액 제안을 보류하도록 코드로 처리했다.

## 마지막 Opus 금액 답변 확인

의도 분류는 대역을 사용하고 답변 생성만 Opus API로 1회 호출했다. 답변 형식·거래 ID 인용·예산 범위 자동 검사는 통과했고 선택지는 50,000원이었다. 다만 문장에 **선택한 지인과 거래의 연결이 확인되지 않았다**는 부정확한 표현이 남았다.

이후 모델 입력에 `history.person_id`와 각 거래의 `contact_person_id`를 명시하고, 개인 거래 연결과 부고 상주의 동일인 확인을 구별하도록 프롬프트를 보완했다. 이 변경과 조문 시간 표현 보완은 아래 추가 승인 12회로 재검증했다.

## 추가 승인 후 두 모델 재검증

원본 결과: [추가 승인 후 재검증 JSON](results_20261031_000345_852165.json)

이력·금액·참석 3개 질문을 두 모델에 각각 의도 분류부터 답변까지 실행했다. 두 모델 모두 3개 사례의 자동 형식·상태·근거 ID 검사는 통과했다. 이력 답변에서 지인과 거래의 연결을 확인했고, 참석 답변에서는 행사 기간과 세부 조문 가능 시간의 확인 필요성을 구분했다.

다만 두 모델의 금액 답변에는 `E001`이 **가상 사용자의 본인 결혼 행사**인데 지인 김도윤의 결혼 행사인 것처럼 표현한 문제가 있었다. 자동 검사 통과만으로 문장의 사실성까지 보장하지 못한 사례다.

이후 행사 주체인 `subject_relation`을 모델 입력에 추가했다. 또 금액 기능에서는 모델의 자유 서술 대신 확인된 받은·낸 금액과 예산을 코드로 요약하고, 모델이 제안하고 예산 범위를 통과한 금액을 별도로 표시하도록 변경했다. 이 최종 변경은 추가 12회 한도를 모두 사용한 뒤 이뤄져 **실제 모델 재검증을 하지 못했다**. 오프라인 자동 테스트와 모델 대역을 이용한 브라우저 확인에서 잘못된 모델 서술이 금액 답변에 그대로 표시되지 않는 것을 확인했다.

## 화면 및 통합 경계

로컬 Chromium에서 111개 가상 계정 목록, `U001`의 기록과 부고, 상주 소속 차이와 직접 확인, 예산 재질문과 금액·근거 표시, `U012`의 직접 친구·친구의 친구 부고, 계정 변경 시 대화 초기화를 확인했다. 이 화면 확인의 모델 답변은 대역을 사용했으며 실제 모델 시연 영상이 아니다.

시제품의 계정 선택은 로그인이나 운영 환경의 접근 제어를 검증한 것이 아니다. 실제 팀 서비스에 통합한 뒤 인증된 사용자와 DB 권한을 다시 확인해야 한다.

## 사용자 시연 중 발견한 부고 확인 문제와 보완

부고 선택 후 상주·장소 정보를 확인하기 어렵고, 누구의 부고인지 모르는 상태에서 금액을 물으면 모든 지인을 선택하도록 요구하는 문제가 발견됐다. 상주 정보와 가상 장소·시간을 먼저 표시하고, 해당 상주 이름과 같은 지인 후보·소속 비교·모름 선택지를 제공하도록 수정했다. 확인하지 않은 상주와 개인 거래는 연결하지 않는다.

질문 분류 프롬프트를 조정하고 명시적인 금액 질문에 대한 보정을 추가했다. 보완 후 자동 테스트 50개와 Chromium 대역 검증은 통과했다. 이전 실제 모델 검증 한도에 이미 도달했으므로 이 변경은 **실제 모델로 재검증하지 않았다**.

이후 최대 예산 질문에 `없어`라고 답하면 같은 질문이 반복되는 문제가 확인됐다. 모호한 답에는 예산 미정과 지출 곤란을 구분하는 선택지를 제공하고, 미정에는 확인된 거래 근거를 보여주며 금액 제안은 보류하도록 보완했다. 전체 자동 테스트 66개와 Chromium 대역 검증을 통과했다. 이 변경에도 실제 모델을 추가 호출하지 않았다.
